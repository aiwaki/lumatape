# Пользовательские шейдеры LumaTape v1

[Русский](SHADER_SPEC.md) | [English](SHADER_SPEC.en.md)

В трее выберите **Добавить эффект из файла…** и откройте `.lumatape.glsl`. Движок проверяет формат и компилирует файл с помощью настоящего драйвера. После успешной проверки файл сохраняется в библиотеке и появляется в меню **Эффект**. Импорт и выбор — отдельные операции: при отсутствии игры или несовместимой настройке искажений файл сохраняется, но не активируется. При ошибке остаётся прежний эффект; объяснение доступно в системном сообщении и **Сервис → Последняя ошибка…**.

[В руководстве есть готовый пример запроса для AI](shaders/README.md). Сохраните ответ как `.lumatape.glsl` и откройте его через меню. Кнопки AI, редактора и вставки кода в приложении нет. Приложение ничего не отправляет; одной фразы «сделай шейдер LumaTape» без контракта может быть недостаточно. Shadertoy, ReShade, Slang и многопроходные цепочки требуют адаптации.

Шейдер задаёт готовый вид. В приложении нет ползунков эффекта или общей интенсивности; явный выбор эффекта и включение используют 100%. Новые файлы должны содержать `parameters: []`, художественные значения — константы GLSL. Поддержка параметров v1 и интенсивности в JSON/CLI сохраняется для совместимости.

## Файл

UTF-8, до 64 KiB. Допускаются BOM, CRLF и один Markdown-блок `glsl` при вставке. Сначала JSON-комментарий, затем функция GLSL. Препроцессор и `main()` создаются приложением.

```glsl
/* LumaTape
{
  "version": 1,
  "name": "Тёплый свет",
  "description": "Готовый тёплый оттенок",
  "coordinates": "preserve",
  "parameters": []
}
*/
vec3 lumatape(vec2 uv) {
    vec3 color = ltSample(uv);
    return mix(color, color * vec3(1.08, 0.97, 0.84), 0.6);
}
```

| Имя | Значение |
|---|---|
| `uv` | Нормализованные координаты области изображения; начало сверху слева. Форма CRT уже учтена оболочкой. |
| `ltSample(uv)` | Цвет игры в SDR sRGB; приложение применяет crop/source UV и ограничивает выборку краями. |
| `ltResolution` | Физический размер области изображения, `vec2`, не всего монитора. |
| `ltTime` | Секунды; при freeze — 0. |
| `ltParams[8]` | Совместимость v1: параметры в порядке `parameters`; при выборе старого файла берутся его `default`. Неиспользуемые слоты — 0; при `parameters: []` все восемь равны 0. |
| Возвращаемый `vec3` | Обработанный RGB sRGB. Alpha, bypass, общую интенсивность и форму рассчитывает приложение. |

ABI v1 по-прежнему принимает до 8 параметров с уникальными читаемыми именами. Для каждого нужны конечные `min < max`, положительный `step <= max-min` и `default` внутри диапазона; границы по модулю до 1 000 000. Существующие файлы продолжают работать, но приложение не создаёт ползунки по этому описанию. Для нового законченного эффекта используйте пустой массив и константы, как в примере.

Не умножайте результат на общую интенсивность: оболочка рендера сама смешивает исходный и обработанный кадры. Сохранённые JSON/CLI-настройки `effects.intensity` остаются совместимыми; при 0 пользовательская функция полностью обходится, фильтр и форма отсутствуют, независимый 4:3 остаётся. Загрузка существующего профиля сама не переписывает его значения; явный выбор, включение или применение в приложении устанавливает интенсивность 1.

`coordinates: "preserve"` — заявление автора, что шейдер сохраняет геометрию, а не математическое доказательство совпадения кликов. Для реального искривления или смещения требуется `"warp"`; его нельзя включить в режиме **Точные клики**. Для него выберите **Настройки → Искажения изображения → Разрешить произвольные искажения**. Клавиатура и мышь работают в обоих режимах; второй разрешает изменения картинки, при которых видимая цель может не совпадать с местом клика. Проверяйте круги, текст и края на тестовой сцене. Изменение цвета, зерно, строки и короткие локальные фильтры обычно используют preserve.

Встроенная форма **Выпуклый CRT** применяется оболочкой отдельно от пользовательского GLSL. В Full она доступна в режиме **Точные клики** и `coordinates: "preserve"`: приложение проецирует рисунок системного курсора на известную геометрию экрана, сохраняя Windows-ввод. Для `"warp"` проекция отключена — ABI v1 не описывает обратное преобразование произвольного шейдера. Пометка `preserve` не должна скрывать собственную деформацию и не включает универсальное переназначение мыши.

В v1 доступны обычная математика GLSL 330 и вспомогательные функции. Недоступны собственные uniforms, `in/out/inout`, `layout`, `discard`, `main`, `gl_*`, служебные `uSource*`/`frag`, директивы `#`, внешние файлы/текстуры и история кадров. Циклы `for/while/do` не поддерживаются; небольшие ядра размытия пишутся развёрнутыми выборками. Это намеренно небольшой однопроходный интерфейс. При ошибке компиляции импорт завершается с ошибкой; рабочее изображение не заменяется чёрным кадром.

## Хранение и границы

Идентификатор — SHA256 нормализованного файла. Шейдеры сохраняются в `%LOCALAPPDATA%\LumaTape\Shaders`; импорт новой версии создаёт новый ID, прежний остаётся доступен. Конфигурация хранит ID и восемь чисел, исходный код не попадает в диагностику. Не меняйте содержимое файла под прежним ID — импортируйте обновлённый файл. Библиотека ограничена 128 шейдерами. Примеры: [Amber CRT](../examples/shaders/amber-crt.lumatape.glsl), [Cold Bleed](../examples/shaders/cold-bleed.lumatape.glsl); они также показывают совместимый ABI параметров v1.

Пользовательские фильтры требуют Full. Автоматическая обработка выбирает доступный способ передачи кадров; полный цветовой шейдер нельзя воспроизвести в Lightweight. В приложении с треем нет встроенного предпросмотра. Для проверки используется отдельная тестовая сцена через «Сервис → Тестовая сцена»; выберите её как игру и включайте/выключайте эффект.

Ограничения размера и языка не изолируют GPU-драйвер. Сложный код может медленно компилироваться или исполняться; приложение не обещает жёстко прервать зависший вызов драйвера. Поддержка пользовательского кода не означает, что любой сгенерированный результат визуально корректен или производителен. Проверки импортов, транзакций и реального рендера перечислены в [протоколе Windows](WINDOWS_VALIDATION.md).
