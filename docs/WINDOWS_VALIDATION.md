# Проверка в Windows

[Русский](WINDOWS_VALIDATION.md) | [English](WINDOWS_VALIDATION.en.md)

Протокол охватывает текущий **нативный трей Tauri** и движок рендера на Go.
Это перечень проверок, а не утверждение, что все сочетания уже прошли проверку.
Записывайте результаты с точным релизом, хешами бинарных файлов и параметрами
среды. Браузерные демонстрации и сохранённые прототипы React не подтверждают
работу поставляемого интерфейса.

## Кандидат и среда

Используйте Windows 10 версии 2004 (сборка 19041) или новее, бинарные файлы x64,
SDR и драйвер OpenGL 3.3. Начните с одноразового тестового профиля и комплектной
тестовой сцены. Сохраняйте обычный профиль и записи восстановления. Проверяйте
GUI в интерактивной сессии Windows: Session 0 не позволяет подтвердить захват,
фокус или ввод.

Запишите релиз/тег, SHA256 ZIP или установщика, хеши EXE/DLL, сборку и архитектуру
Windows, GPU/драйвер, размер монитора, частоту обновления, DPI и выбранный бэкенд.
Запрошенный и фактический способ обработки записывайте отдельно. Наличие DLL или
расширения OpenGL не доказывает работоспособность GPU interop. Для обновлений
установленной версии используйте дополнительный
[протокол проверки обновлений](UPDATES.md).

Переносимый кандидат распакуйте в новый путь с пробелами и символами вне ASCII,
например `C:\LumaTape tests\Проверка`. Проверьте контрольную сумму и содержимое
архива; повторите проверку с запретом записи рядом с исполняемым файлом.
Конфигурация, библиотека шейдеров и логи должны оставаться в профиле пользователя.
Не выводите код завершения 0 из `Finished=true`, снимка экрана или пустого
`ExitCode`.

Перед каждым изменением определите PID, путь к исполняемому файлу, время создания
процесса и HWND только для объектов своего теста. Сохраните эти идентификаторы в
локальных материалах проверки. Не завершайте все процессы по имени и не
останавливайте независимый watchdog восстановления вместе с его владельцем.
Локальные материалы могут содержать заголовки окон и полные пути; проверьте их
и удалите приватные данные перед передачей другим. В релизы эти материалы не
входят.

## Сборка и переносимый пакет

Для сборки Windows нужны Go, Python, Node/npm, Rust MSVC, Visual Studio C++ tools и
Windows SDK 10.0.26100 или новее. Версия SDK сборки не повышает минимальную версию
Windows для запуска. Шаги сборки описаны в
[руководстве по desktop-хосту](../desktop/src-tauri/README.md).

Запускайте проверки изменённых компонентов, сохраняя результаты ранее успешных
проверок незатронутых частей:

```sh
sh scripts/check.sh
(cd desktop && npm run test:host)
python3 -m unittest discover -s scripts -p 'test_package_desktop.py'
python3 -m unittest discover -s scripts -p 'test_prepare_update.py'
python3 -m unittest discover -s desktop/scripts -p 'test_*licenses.py'
```

Сборка Cargo использует `Cargo.lock` и `--locked`. Исполняемые файлы Go-тестов для
Windows нужно также запустить в Windows и отдельно записать код завершения.
Нативный `lumatape_capture_abi_smoke.exe` проверяет ABI захвата и жизненный цикл
ошибок; успешный захват он не подтверждает. Упаковщик проверяет обязательные
экспорты, включая `open_ex` и `get_stats`, и не принимает старую DLL только с GPU.

Проверки шейдеров с чтением результата на Mac отделены от проверок драйвера
Windows, DWM и WGC. Исполняемая матрица возможностей и детерминированные тесты
геометрии/переходов проверяют правила, а не тысячи реальных сеансов игр и дисплеев.

## Нативный трей и обычное использование

| Сценарий | Ожидаемое поведение |
|---|---|
| Первый запуск | Один значок Tauri и один движок; нет панели приложения, значка Go в трее или дочернего процесса WebView2. Новый профиль запускается с выключенным эффектом. |
| Повторный запуск | Второй экземпляр завершается без нового движка, оверлея или регистрации горячих клавиш. |
| Меню | Левый и правый клик открывают одно и то же нативное меню. Версия расположена непосредственно над пунктом выхода; пункт «О LumaTape» открывает GitHub-адрес проекта. |
| Язык | Русский язык интерфейса Windows выбирает RU, остальные языки — EN. Регион и формат даты не определяют язык. После смены языка интерфейса Windows перезапустите приложение. |
| Источник | Меню «Игра» показывает реальные окна и различает одинаковые заголовки. Закрытый источник не заменяется другим процессом с таким же заголовком. |
| Статус | При выключенном эффекте выберите источник и сразу откройте трей. Меню и подсказка не должны кратковременно показывать «Работает». Повторите после горячей клавиши, потери фокуса и закрытия источника; включённая настройка сама по себе не означает видимый эффект. |
| Включение | Откройте «Сервис → Тестовая сцена», выберите её в меню «Игра», выберите эффект и включите его. Верните фокус самостоятельно; проверьте свежие кадры захвата и обычный ввод. |
| Настройки | Изменения применяются сразу, отмеченные пункты соответствуют применённому состоянию, а для недоступных сочетаний указана причина. Ползунка интенсивности и ручного редактора параметров шейдера в трее нет. |
| Ошибка | Отсутствие DLL захвата, сбой устройства/источника или конфликт горячих клавиш не оставляют непрозрачную поверхность поверх игры. Сообщение об ошибке не должно утверждать, что прежняя рабочая конфигурация успешно заменена. |
| Отключение/выход | Поверхность и проекция курсора исчезают; принадлежащие приложению изменения формата восстанавливаются. Ошибки очистки остаются видимыми и допускают восстановление. Перезапуск не должен скрыто повторять изменение формата, отменённое аварийным отключением. |

Нативные инструменты, привязанные к идентичности процесса, запускаются из корня
репозитория:

```powershell
# Set these to the current test bundle, retained process handle and evidence folder.
./scripts/windows-tray-only-smoke.ps1 -Bundle $Bundle -HostProcessId $App.Id -Output "$Evidence/inventory.json"
./scripts/windows-tray-menu-smoke.ps1 -Bundle $Bundle -HostProcessId $App.Id -Output "$Evidence/menu.json"
./scripts/windows-testcard-fullscreen-smoke.ps1 -Exe "$Bundle/engine/lumatape-testcard.exe" -Output "$Evidence/fullscreen.json"
# $TestExecutable — текущий Rust test executable из cargo test --no-run.
./scripts/windows-testcard-close-smoke.ps1 -TestExecutable $TestExecutable -Output "$Evidence/delayed-close.json"
```

Последняя проверка создаёт собственное скрытое HWND после первой попытки закрытия
и проверяет повторную отправку `WM_CLOSE`. Дополнительно откройте тестовую сцену и
сразу выберите «Выход»: приложение должно закрыться с первой команды. Если сцена
не закрылась, движок должен остаться доступным для повторной попытки.

Сначала прочитайте параметры и область действия каждого инструмента. Проверка
состава процессов только читает состояние; проверка меню открывает собственное
нативное меню; `-MenuPath` выполняет реальную команду. Инструмент полноэкранной
проверки владеет созданными им процессами тестовой сцены и через сообщения Win32
проверяет F11, Alt+Enter, Escape, нативную кнопку и точное восстановление окна.
Это не доказывает доставку команд с физической клавиатуры.

Для изолированной проверки меню RU/EN `windows-localization-smoke.ps1` ожидает
**переносимый кандидат без настроенного канала обновлений** и отсутствие обычного
запущенного экземпляра. Он создаёт собственные временные профили и не включает
эффект. Подмена языка только для теста не меняет настройки Windows. Обычное
определение языка системы проверяйте отдельно. Не запускайте этот инструмент
без адаптации на кандидате с настроенным каналом обновлений.

### Автозапуск и команды «Сервиса»

Перед проверкой сохраните наличие, тип и данные только значений `LumaTape` в
`HKCU\Software\Microsoft\Windows\CurrentVersion\Run` и
`HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\StartupApproved\Run`.
После проверки восстановите только записи, изменённые вашим тестом; не заменяйте
целиком ветки реестра и не перезаписывайте чужие изменения.

1. После чистой NSIS-установки автозапуск выключен и запись `Run` отсутствует.
   Включите и выключите «Сервис → Запускать при входе в Windows». Проверьте
   отметку меню и реестр: команда содержит точный путь к установленному EXE в
   кавычках, в том числе при пробелах и кириллице в пути. Выключение убирает запись.
2. Отключите LumaTape в Диспетчере задач. Повторное открытие меню и перезапуск
   приложения должны только прочитать этот выбор. Включение разрешено лишь после
   явной команды пользователя; проверьте её отдельно.
3. Откройте переносную ZIP-копию и копию установленной папки из другого места.
   Пункт объясняет ограничение; эти копии не должны создавать автозапуск или
   заменять запись, принадлежащую установленному приложению.
4. Проверьте обновление с включённым и выключенным автозапуском, включая
   отключение в Диспетчере задач: выбор сохраняется. Обычная деинсталляция удаляет
   собственную запись. Переключение, ожидающее в очереди при выборе «Выход»,
   отменяется. Если запись в реестр уже началась, выход дожидается её завершения.
5. «Сервис → Открыть папку эффектов» открывает в Проводнике именно
   `%LOCALAPPDATA%\LumaTape\Shaders` текущего пользователя. Сверьте путь с библиотекой
   движка; одно открытие не импортирует и не включает эффекты. «О LumaTape» открывает
   `https://github.com/aiwaki/lumatape` в браузере по умолчанию.

## Эффекты и пользовательские шейдеры

Проверьте Subtle CRT, CRT Classic, Soft TV, VHS Light и VHS Tape в исходном
масштабе изображения. Используйте цветовые границы, мелкий текст, градации серого,
круг, сетку, чёрный/белый, движущийся объект и цели HUD в углах. Subtle CRT
намеренно сдержан; остальные пресеты должны заметно различаться. Одной числовой
разницы PNG недостаточно, чтобы оценить читаемость, мерцание или задуманный эффект.

Сравните плоскую форму, скруглённый CRT и выпуклый CRT. В углах не должен
проступать необработанный прямоугольник. Отключение убирает рамку и кривизну.
Выбор эффекта сохраняет идентичность источника, выбранный формат, сочетания клавиш
и состояние включения; трей использует полную интенсивность шейдера. Старый обход
обработки при нулевой интенсивности относится к тестам движка, а не к управлению
в трее. Lightweight не обеспечивает полноценную обработку пикселей.

Импортируйте оба [примера шейдеров](../examples/shaders/) через пункт «Добавить
эффект из файла…». Проверьте настоящую компиляцию GLSL, активацию, повторный выбор,
перезапуск и сохранение пользовательских значений. Некорректные UTF-8, метаданные
или GLSL, слишком большой файл и библиотека только для чтения должны выдавать
понятную ошибку, не заменяя последнюю рабочую программу. Допустимые входные данные
и ограничения заданы в [контракте шейдеров](SHADER_SPEC.md).

## Ввод, фокус и геометрия

В режимах **Настройки → Искажения изображения → Точные клики** и **Разрешить
произвольные искажения** работают клавиатура и мышь. «Точные клики» сохраняют
соответствие изображения обычному вводу; встроенная выпуклая форма проецирует
рисунок курсора, не меняя координаты Windows и не внедряя ввод в игру.
Произвольные искажения разрешают Crop, Stretch, произвольное соотношение сторон
изображения и пользовательские шейдеры `warp`, при которых видимые цели могут не
совпадать с фактическим местом клика.

Проверьте наведение и клики по всем пяти целям тестовой сцены, перетаскивание с
удержанием кнопки, колесо, потерю фокуса, сворачивание/восстановление, закрытие,
изменение размера, полноэкранный режим и перемещение источника. После отключения,
выхода или ошибки не должно быть повторных кликов, залипших кнопок или оставшейся
проекции курсора. При смене фокуса приложение не должно забирать его обратно.
Проверьте обе стороны каждого края окна и повторите проверку на физической
Windows-системе: снимок VM может не содержать курсор хоста.

Используйте [специальные инструменты ввода](../scripts/windows-ui-smoke/README.md).
Они фиксируют идентичность цели, проверяют реальные счётчики тестовой сцены и
отпускают внедрённые удержания при ошибке. SendInput в гостевой системе
подтверждает обработку команд Windows, но не доставку физического ввода с
клавиатуры Mac через Parallels. Успешная регистрация RegisterHotKey и получение
сочетания — отдельные проверки. По умолчанию используются Ctrl+Shift+9
(переключение) и Ctrl+Shift+0 (аварийное отключение); существующие сочетания не
меняются. Проверьте конфликт регистрации, сохранив рабочее аварийное сочетание.

## Формат и восстановление

В трее доступны «Исходный формат» и разрешение Windows. Маски и
изменение размера игрового окна убраны из управления; активный старый профиль
по-прежнему читается и может быть восстановлен. Для обычной игры в 4:3 сначала
выберите разрешение 4:3 внутри игры. 1280×1024 — это 5:4. Переключение режима
Windows не гарантирует внутреннее разрешение/FOV игры или способ масштабирования
монитора.

Для изменений дисплея используются только режимы из перечня Windows;
предварительная проверка и подтверждение в течение 15 секунд обязательны.
Пункт «Подтвердить видеорежим» появляется только во время ожидания подтверждения.
Проверьте подтверждение, тайм-аут, позднее подтверждение, аварийное отключение,
обычный выход, завершение главного процесса и последующее внешнее изменение
дисплея. Восстанавливайте только изменения, которыми всё ещё владеет LumaTape.
Проверьте ошибки подготовки, применения, чтения результата, отката и записи
журнала восстановления. Во время проверки отказа главного процесса watchdog
должен продолжать работать.

Сценарии, меняющие дисплей, выполняйте только на тестовом дисплее с возможностью
восстановления. Без явно заданных аргументов сценария, устройства и watchdog
инструмент `windows-display-smoke` только читает состояние. Поддельный драйвер или
виртуальный дисплей не подтверждают восстановление физического дисплея.

Проверки геометрии охватывают 320×200 с соотношением сторон изображения 4:3,
640×480, 960×720, 1280×1024 и 1920×1080; окна с рамкой и без рамки;
100/125/150/200% DPI; отрицательные координаты и смену монитора/адаптера. Проверяйте
минимальные размеры, заданные игрой, и устаревшие кадры после каждого перехода
геометрии.

## Длительные прогоны и материалы проверки

Измеряйте после прогрева с отключённым захватом PNG. Сохраняйте длительность,
число свежих кадров, распределение возраста кадров, время передачи/отправки,
задержки, прерывания фокуса и рост памяти. Время GPU-шейдера само по себе не
равно общей задержке. Передача через CPU ограничена 30 FPS; предел не обещает
устойчивые 30 FPS.

Используйте неподвижный источник и детерминированное движение указателя, затем
проверьте реальные игры в оконном режиме и без рамки на физическом оборудовании.
В отчёте разделяйте переносимые тесты, шейдеры Mac, совместимость Windows CPU,
аппаратный GPU interop и обновления через установщик. Явно отмечайте недоступное
оборудование и незапущенные сценарии. Эксклюзивный полноэкранный режим, HDR,
захват всего монитора в Full и обход античита/защиты от захвата не поддерживаются.
